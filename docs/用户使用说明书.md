# 律师文书基础信息与关键事实复核助手 用户使用说明书

当前开发版本：`v0.5.0-dev`

## 1. 工具简介

律师文书基础信息与关键事实复核助手，是一个本地运行的文书辅助复核工具。它用于帮助律师、律师助理、法务人员和文书复核人员，在文书提交、交付或归档前，快速整理并检查文书中的基础信息、关键事实项和可能存在的版本更新风险。

本工具可以辅助发现的问题包括：当事人名称前后不一致、统一社会信用代码格式异常、法定代表人与基础信息表不一致、案号格式异常、金额前后不一致、日期顺序可疑、正文引用的证据编号未出现在证据目录中、文书中残留“待补充”等模板内容。

**本工具仅用于辅助人工复核，不构成法律意见，最终判断由律师或相关人员完成。**

## 2. 适用场景

本工具适合用于以下场景：

- 文书提交前基础信息复核。
- 当事人名称、统一社会信用代码、法定代表人、地址复核。
- 案号、法院、仲裁机构名称复核。
- 金额、日期、合同编号复核。
- 证据编号与证据目录一致性检查。
- 没有基础信息表时，先抽取字段，让用户去企查查、内部数据库或案件台账核验。
- 实习生、律师助理或法务人员进行初步文书检查。
- 形成复核工作底稿，便于后续归档、交接或复盘。

## 3. 不适用场景和功能边界

请注意，本工具有明确边界：

- 不自动判断案件胜诉可能。
- 不提供法律意见。
- 不替代律师审查。
- 默认本地运行，不访问第三方网站。
- 外部来源和内部系统信息需人工核对。
- 不自动修改原 Word 文书。
- 不保证 OCR 或文本抽取 100% 准确。
- 不适合直接处理高度复杂或格式极不规范的材料而不做人工检查。

系统输出的所有提示都应理解为“建议人工复核”，不表示系统已经确认文书存在错误。

## 4. 启动方式

### 4.1 Windows 一键启动

适合非技术用户使用。

运行要求：Python 3.10-3.12。v0.4.0-rc1 Windows portable 推荐使用 Python 3.11 或 3.12。若交付包包含 `wheelhouse/`，wheelhouse 必须与目标 Python 版本匹配，例如 cp312 wheelhouse 必须使用 Python 3.12。

1. 解压 `LegalFactReview_v0.4.0-rc1_windows_portable.zip`。
2. 打开 `LegalFactReview` 文件夹。
3. 双击 `start.bat`。
4. 等待窗口提示启动完成。
5. 浏览器访问窗口显示的地址，通常是：

```text
http://localhost:8501
```

6. 使用完成后，关闭启动窗口即可停止服务。

首次启动可能会自动创建 `.venv` 虚拟环境并安装依赖，时间可能较长。如果交付包内包含 `wheelhouse/`，会优先使用离线依赖安装。

如果已存在的 `.venv` 是 Python 3.13 创建的，启动前检查会提示删除 `.venv` 后重试，脚本会用 Python 3.10-3.12 重新创建虚拟环境。离线 `wheelhouse/` 必须与目标 Python 版本匹配。

启动前检查会识别 wheelhouse 中的 Python 标签。如果 wheelhouse 是 cp312 但当前 Python 是 3.11，脚本会提示版本不匹配并停止，请安装 Python 3.12 或重新生成对应版本 wheelhouse。

### 4.2 v0.2.0 案件工作区

案件工作区用于把同一案件或项目下的多份文书复核记录归集管理。用户可以创建案件，填写案件名称、内部案件编号、客户名称、对方主体、案件类型和备注。

选择案件后，单次复核和批量复核生成的 review_id 会关联到该案件；未选择案件时，仍可使用临时复核模式。系统只保存案件信息、文书文件名、文件类型、文件大小、复核结果、待外部复核字段和人工复核记录，不保存完整上传文书正文。

历史复核记录页面可查看 review_id、所属案件、文书文件名、复核模式、findings 数量、高中低风险数量、待外部复核字段数量、人工复核记录数量和创建时间。用户可以重新打开历史记录继续填写人工复核记录，并重新导出 Excel、HTML、Word 或 ZIP 报告。

批量复核支持一次上传多份 DOCX/PDF，并可选上传基础信息表和证据目录。系统会对每份文书分别复核并生成独立 review_id；单个文件失败不影响其他文件。

案件工作区支持导出案件级复核包，包含案件复核汇总 Excel、案件复核报告 HTML，以及每份文书的复核包。

案件内字段差异提示会对同一案件下不同文书的当事人名称、统一社会信用代码、法定代表人、地址、案号、法院名称、合同编号、金额、日期和证据编号做基础字段级对比。该提示仅表示不同文书之间字段不一致，需人工判断是否属于正常版本差异、材料更新或录入错误，不构成法律结论。

## 5. 主界面说明

进入系统后，页面通常包含以下区域：

- **文书上传区**：上传需要复核的 `.docx` 或 `.pdf` 文书。
- **可选资料上传区**：上传基础信息表和证据目录。两者都是可选文件。
- **文书类型选择**：如版本提供文书类型配置，可用于选择不同复核规则。
- **OCR 选项**：用于扫描版 PDF。OCR 是可选能力，需要额外安装依赖，识别结果必须人工复核。
- **开始复核按钮**：上传文件后点击，系统开始解析和复核。
- **复核结果概览**：显示总发现数、高风险数、中风险数、低风险数、涉及字段数等。
- **复核发现表格**：展示系统识别出的风险提示。
- **待外部复核字段清单**：展示从文书中抽取出的字段，并提示建议复核来源。
- **人工复核工作区**：用户填写复核状态、人工确认值、复核来源和备注。
- **报告下载区**：下载 Excel、HTML、Word 或 ZIP 复核包。

## 6. 上传文件说明

### 6.1 文书文件

支持：

- `.docx`
- `.pdf`

说明：

- 普通 PDF 可以直接提取文字。
- 扫描版 PDF 可能无法识别出内容，可以勾选 OCR，或先转换为可复制文字的 PDF。
- 当前工具不会保存完整原文书内容。

OCR 说明：

- OCR 全程本地运行，不上传 PDF 或图片。
- OCR 依赖较大，基础包默认不强制安装。
- 如未安装 OCR 依赖，请运行 `pip install -r requirements-ocr.txt`。
- OCR 来源会标记为 `第1页 OCR 文本` 等形式。
- OCR 可能识别错误，结果必须人工复核。

### 6.2 基础信息表

基础信息表是可选文件。上传后，系统可以将文书中的字段与表中的标准值进行比对。

建议格式：

| 字段名 | 标准值 | 更新时间 | 备注 |
| --- | --- | --- | --- |

示例：

| 字段名 | 标准值 | 更新时间 | 备注 |
| --- | --- | --- | --- |
| 公司名称 | 上海某某智能科技有限公司 | 2026-06-01 | 来自客户资料 |
| 法定代表人 | 张三 | 2026-06-01 | 待核验 |
| 住所地 | 上海市浦东新区某路88号 | 2026-06-01 | 工商信息 |

### 6.3 证据目录

证据目录也是可选文件。上传后，系统可以检查正文引用的证据编号是否出现在证据目录中。

建议格式：

| 证据编号 | 证据名称 | 页码/附件位置 | 备注 |
| --- | --- | --- | --- |

示例：

| 证据编号 | 证据名称 | 页码/附件位置 | 备注 |
| --- | --- | --- | --- |
| 证据1 | 合同 | 附件1 | 原件扫描件 |
| 证据2 | 付款记录 | 附件2 | 银行流水 |

## 7. 两种复核模式

| 模式 | 上传文件 | 系统行为 | 适合场景 |
| --- | --- | --- | --- |
| 单文书字段抽取模式 | 只上传文书 | 抽取字段，生成待外部复核字段清单 | 没有基础信息表或证据目录时 |
| 完整复核模式 | 文书 + 基础信息表 + 证据目录 | 抽取并比对，生成复核 findings | 有结构化资料时 |

### 7.1 单文书字段抽取模式

只上传文书即可运行。系统会抽取文书中的公司名称、统一社会信用代码、法定代表人、地址、案号、法院或仲裁机构、合同编号、金额、日期、证据编号、附件编号等字段。

在这个模式下：

- 系统不会自动核验这些字段是否真实、最新或正确。
- 系统默认本地运行，不访问第三方网站、外部数据库或内部系统。
- 用户需要根据“建议复核来源”，自行去外部系统或内部资料中人工核验。
- 输出重点是“待外部复核字段清单”。

### 7.2 完整复核模式

上传文书、基础信息表和证据目录后，系统进入完整复核模式。

在这个模式下：

- 系统会抽取文书中的字段。
- 系统会将文书字段与基础信息表进行比对。
- 系统会检查正文引用的证据编号是否存在于证据目录中。
- 系统会提示不一致、缺失、格式异常、证据编号缺失、金额不一致、日期逻辑可疑等问题。
- 输出重点是“复核发现”。

## 8. 复核结果如何理解

### 8.1 风险等级

| 风险等级 | 含义 | 建议处理 |
| --- | --- | --- |
| high | 可能影响文书核心事实或提交质量 | 优先人工核对 |
| medium | 可能存在版本差异或信息不一致 | 根据材料复核 |
| low | 格式、提示或轻微异常 | 视情况处理 |

### 8.2 风险类型

- `MISSING_FIELD`：关键字段缺失。
- `INTERNAL_CONFLICT`：文书内部不一致。
- `SOURCE_MISMATCH`：与基础信息表不一致。
- `FORMAT_ERROR`：格式异常。
- `POSSIBLY_OUTDATED`：疑似旧版本信息。
- `PLACEHOLDER_REMAINING`：占位符未删除。
- `EVIDENCE_REFERENCE_MISSING`：证据引用缺失。
- `AMOUNT_INCONSISTENCY`：金额不一致。
- `DATE_LOGIC_WARNING`：日期逻辑提示。

**风险提示表示“建议人工复核”，不表示系统已经确认文书错误。**

## 9. 待外部复核字段清单

待外部复核字段清单通常包含：

- 字段类型。
- 提取值。
- 角色 / 上下文。
- 出现位置。
- 置信度。
- 建议复核来源。
- 建议动作。

建议使用方法：

1. 先查看高价值字段，例如公司名称、统一社会信用代码、法定代表人、案号、金额。
2. 根据建议复核来源，去企查查、国家企业信用信息公示系统、法院系统、内部客户库、案件台账、合同台账、财务台账等资料中核验。
3. 把核验结果填入人工复核工作区。
4. 导出复核包归档。

字段清单只是从当前文书中自动抽取的结果，外部来源仍需人工核对。

## 10. 人工复核工作流

每条字段可以记录：

- 复核状态。
- 人工确认值。
- 复核来源。
- 复核备注。

复核状态含义：

| 状态 | 含义 |
| --- | --- |
| 未复核 | 还没有人工核验 |
| 已确认 | 人工核验后认为当前值可用 |
| 需修改 | 人工核验后发现文书值需要修改 |
| 已忽略 | 该项暂不处理或无需处理 |

复核来源可以包括：

- 企查查。
- 国家企业信用信息公示系统。
- 法院系统。
- 律所案件台账。
- 内部客户库。
- 合同原件。
- 合同台账。
- 对账单。
- 发票。
- 客户确认材料。
- 其他。

**人工复核记录会保存到本地 SQLite，用于形成工作底稿。**

如果状态选择“需修改”，建议填写人工确认值，并在备注中说明核验依据或材料来源。

## 11. 报告导出

| 导出类型 | 文件格式 | 内容 | 适合场景 |
| --- | --- | --- | --- |
| 复核工作底稿 | Excel | findings、外部复核字段、人工复核记录 | 二次筛选、归档 |
| 复核报告 | HTML | 可读报告 | 快速查看、演示 |
| Word 复核摘要 | DOCX | 面向律师的复核摘要 | 文书工作流、归档 |
| Word 复核提示版 | DOCX | 在原 DOCX 副本中插入复核提示块和文末汇总 | 律师直接在 Word 中查看提示 |
| 完整复核包 | ZIP | Excel + HTML + DOCX | 交付、归档、留痕 |

说明：

- 报告不会包含完整原文书内容。
- 身份证号、手机号、统一社会信用代码等敏感字段会尽量脱敏。
- 导出的报告仍需人工判断。
- ZIP 复核包适合随案件材料或内部工作底稿一起归档。

### 11.1 Word 复核提示版

Word 复核提示版仅支持 DOCX 原文书。上传 DOCX 并完成复核后，系统可生成：

```text
<原文件名>_复核提示版.docx
```

该文件是新生成的副本，系统不会覆盖原始 Word 文件，也不会自动修改原文正文。系统会尽量在对应段落或表格附近插入“【复核提示】”块；无法定位的提示会进入文末“未定位复核提示”。

提示版文末包含“复核提示汇总”，包括高风险优先处理清单、未定位复核提示、待外部复核字段、人工复核记录和免责声明。所有提示仍仅表达为“建议人工复核”，不构成法律意见。

PDF 文书仍可导出 Word 复核摘要，但不生成原文提示版。历史记录不保存原文书正文，因此历史详情不能重新生成 Word 复核提示版。

Word 复核提示版包含原文内容，用户应按案件材料保密要求妥善保存和流转。

## 12. 数据保存与隐私说明

请重点注意：

- 默认本地运行。
- 不上传文书到互联网。
- 不调用外部 API。
- 默认本地运行，不访问第三方网站或外部系统。
- SQLite 默认保存在 `data/review_runs.sqlite`。
- 导出报告保存在用户浏览器下载位置或 `exports/`。
- 用户应自行保护 `data/`、`exports/` 和导出 ZIP。
- 如需清空历史记录，可以关闭工具后删除 `data/review_runs.sqlite`。

系统会保存复核发现、字段抽取值、人工复核状态、人工确认值、复核来源、备注和复核时间，但不会保存完整上传文书内容。

## 13. 示例使用流程

### 13.1 只有一份 PDF 文书

1. 启动工具。
2. 上传 PDF 文书。
3. 不上传基础信息表和证据目录。
4. 点击“开始复核”。
5. 查看“待外部复核字段清单”。
6. 去企查查、法院系统或内部数据库人工核验。
7. 在人工复核工作区填写复核状态、人工确认值、复核来源和备注。
8. 导出 ZIP 复核包。

### 13.2 有文书、基础信息表、证据目录

1. 启动工具。
2. 上传文书。
3. 上传基础信息表。
4. 上传证据目录。
5. 点击“开始复核”。
6. 查看高风险 findings。
7. 优先处理 `SOURCE_MISMATCH`、`EVIDENCE_REFERENCE_MISSING`、`AMOUNT_INCONSISTENCY` 等问题。
8. 在人工复核工作区填写核验结果。
9. 导出 Word 复核摘要或 ZIP 工作底稿。

## 14. 常见问题 FAQ

### Q1：为什么我只上传文书也能运行？

因为系统会进入单文书字段抽取模式，只抽取字段，不做外部核验。

### Q2：不上传基础信息表时，系统会判断公司名称是否正确吗？

不会。系统只会提取公司名称，并提示你去企查查、国家企业信用信息公示系统或内部客户库人工复核。

### Q3：系统会访问外部网站吗？

默认不会。系统本地运行，外部来源需由用户自行人工核对。

### Q4：系统会上传我的文书吗？

默认不会。工具本地运行，不调用外部 API。

### Q5：为什么 PDF 没有识别出内容？

可能是扫描版 PDF。可以启用 OCR，或转换为可复制文字的 PDF。

### Q6：风险等级 high 是否表示文书一定错误？

不是。`high` 只表示优先复核，不代表该项已经被判定为错误。

### Q7：人工复核记录保存在哪里？

保存在本地 SQLite，默认路径为 `data/review_runs.sqlite`。

### Q8：如何清空历史记录？

关闭工具后删除 `data/review_runs.sqlite`。

### Q9：是否可以直接修改原文书？

当前版本不自动修改原文书。用户应在 Word 中人工修改。

### Q10：这个工具能替代律师审查吗？

不能。它只用于辅助发现事实项和格式问题。

## 15. 已知限制

- 扫描版 PDF 需要 OCR 或预处理。
- 复杂排版 PDF 可能提取不完整。
- 字段识别基于规则和启发式，可能漏识别或误识别。
- 不接入外部数据库。
- 不自动核验工商、法院或案件系统信息。
- 不自动修改 Word 原文。
- 不构成法律意见。

## 16. 建议工作规范

- 提交前至少复核 high 风险项。
- 对主体、案号、金额、日期、证据编号优先人工核验。
- 外部核验后填写人工确认值和复核来源。
- 导出 ZIP 复核包作为工作底稿。
- 对重要案件不要只依赖自动抽取结果。
- 定期清理本地历史数据和导出文件。

## 17. 规则配置中心

规则配置中心用于配置复核规则、文书类型模板和字段词典。入口位于侧边栏“规则配置”。

可配置内容包括：

- 已启用风险类型。
- 风险类型默认等级。
- 占位符模式。
- 外部复核来源和建议动作。
- 文书类型模板。
- 字段词典 alias。
- YAML / JSON 配置导入与导出。
- 恢复默认规则配置。

系统会校验配置文件。风险类型必须来自系统支持的枚举，severity 只能是 `low`、`medium`、`high`，建议动作必须包含“建议人工复核”，不得包含绝对化错误判断或法律结论。

配置错误时系统会回退到默认规则配置，并在规则配置中心显示提示。导入失败不会覆盖旧配置。每次成功导入、保存或恢复默认配置，系统会写入本地配置历史记录；该记录只保存配置变更元数据，不保存上传文书内容。配置中心用于调整辅助复核规则，不代表系统能够自动完成法律判断。

不同文书类型模板会影响必填字段范围，例如民事起诉状会重点关注主体、案号、法院、金额和证据编号。字段差异和复核提示仍只表示“建议人工复核”，不构成法律意见。
